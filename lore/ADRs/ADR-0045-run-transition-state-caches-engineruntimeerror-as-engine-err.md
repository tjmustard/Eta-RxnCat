Context: red team F3 — EngineError includes host and input failures (EngineUnavailableError: CUDA or model file missing; EngineInputError). Caching them all as engine_error would freeze transient failures into the store and silently degrade an ensemble on its second run.
Decision (mission release-0.6.0 R3): run_transition_state caches only EngineRuntimeError, as a completed failure row {failed_reason: "engine_error", message, error_type} in the stage being run (ts_opt or frequency); ScfConvergenceError keeps its own row; EngineUnavailableError and EngineInputError re-raise and leave no row. In an ensemble an engine_error member is excluded with that reason, and any engine_error exclusion in a Tier 4 ensemble fails the acceptance record (visible to TJ).
