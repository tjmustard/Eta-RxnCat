Decision (resolve, replan 7, R45). This supersedes the mechanism of ADR-0006 and ADR-0011; their policies stand (allow-list intent, the geometric 1.1.1 exception, TJ Q1 A exemptions).

The licence gate is `tools/licence_gate.py`, a stdlib-only script run by the target environment's interpreter. It is configured in `[tool.eta-rxncat.licence-gate]` and replaces `pip-licenses --partial-match --allow-only`.

Why the old mechanism was replaced: partial matching passed matscipy, whose LGPL full-text License field contains "MIT" inside "PERMITTED". It also hid MPL-2.0 inside SPDX `AND` expressions (tqdm, orjson). pip-licenses cannot evaluate `AND`.

Rules:
- Each package's verdict comes from the first source present:
  1. the SPDX `License-Expression`, with AND/OR/WITH/parentheses;
  2. otherwise the exact classifier map, where several classifiers are alternatives;

- Anything unrecognised fails, and there is no substring matching.
- Exemptions are version-pinned per profile (`base`, `gpu`, `mlip-mace`, `mlip-uma`).
- One NVIDIA name-plus-proprietary-licence rule applies in the torch profiles only.
- A stale exemption (package absent) fails.
- The allow-list in SPDX ids adds `Zlib` and `CC0-1.0`: permissive, carried by numpy in the core install, and already passing by substring before.

Trade-off:
- Rejected: keeping pip-licenses with exact matching. It cannot do SPDX `AND`, and its OR-over-names semantics would still pass "MPL-2.0 AND MIT"-style metadata wrongly or fail it for the wrong reason.
- Rejected: adding a third-party licence checker. It is a new dependency with its own semantics.
- Chosen: about 150 lines of tested project tooling with deterministic, documented semantics.

Cost: classifier and name maps need upkeep when a new package uses an unseen string. That fails closed, so it surfaces as a gate failure rather than a silent pass.

Decision (resolve, replan 10, R52; slice 09). Proposed to supersede ADR-0012, which is still PROPOSED and unapproved; the supersession itself is left to the lore approval gate.

ArtifactStore's open sequence runs under ONE wall-clock deadline, `open_timeout_s` (default 5.0 s):
1. validate the timeout;
2. check the path;
3. connect;
4. read user_version, and reject anything other than 0/1 before any write;
5. switch to WAL;
6. BEGIN IMMEDIATE, create or check the schema, COMMIT;
7. restore busy_timeout to 5000 ms for normal use.

Steps 4, 5 and 6 each run through one busy step:
- before each attempt it sets busy_timeout to the remaining milliseconds;
- it retries only on SQLITE_BUSY or SQLITE_LOCKED, with backoff starting at 5 ms, doubling, capped at 100 ms;
- when time runs out it raises StoreBusyError, chained to the last OperationalError.
Everything else propagates.

Why ADR-0012 was not enough. It bounded only the WAL switch, after a version read governed by a separate 5 s busy_timeout. The build seat measured this: under an EXCLUSIVE holder, the read blocked 5.007 s and then raised a raw OperationalError('database is locked'). That contradicted the contract that openers either succeed or fail only with StoreBusyError after a bounded wait.

Verified by resolve with SQLite 3.46.1:
- EXCLUSIVE or IMMEDIATE holder past the deadline → StoreBusyError at 0.300 s (timeout 0.3);
- holder released after 0.3 s → WAL open in about 0.33 s;
- barrier race at N = 2, 6, 16 → 0 errors in 300 trials;
- foreign user_version-7 file under an EXCLUSIVE holder → StoreBusyError, file unchanged.

Trade-off:
- Rejected: weakening the proof to an IMMEDIATE-only holder. A real EXCLUSIVE holder would still have leaked a raw error after 5 s.
- Rejected: catching all OperationalErrors. That hides real faults.
- Chosen: one deadline and one documented error class, at the cost of a slightly more complex open path.

## Context

The UMA TS1b_x(graft) ensemble pre-relaxation stalled in 3 of 13 runs at the same inputs (mission
HF-13). Six faulthandler dumps, filtered to eta frames plus a count of geomeTRIC frames, show a live
loop inside the injected geomeTRIC black box. The loop runs numpy eigh/svd between engine calls,
with no engine frame and an idle GPU. eta's `maxiter` does not bound it, and eta seeds geomeTRIC's
RNG, so the trigger is run-to-run engine noise. The optimizer runs in-process (ADR-0024).

## Decision

The ensemble pre-relaxation runs under an in-process wall-time budget (default 600 s, about 12× the
healthy maximum).
- A watchdog thread raises `PreRelaxTimeout`, a `BaseException`, into the calling thread with
  `PyThreadState_SetAsyncExc`. It re-sends every second until the guarded call exits and clears
  any pending exception on exit.
- The member is excluded as `pre_relax_failed:PreRelaxTimeout` with its wall time, the failure row
  is cached, and the ensemble continues.
- The optimizer stays in-process; ADR-0024 is unchanged. P-RFO is not guarded.

## Consequences

- A stall costs at most the budget and can no longer hang an E2E, acceptance or verdict run.
- The cause stays inside the black box. A cached timeout persists in that store; a fresh store
  retries.
- The mechanism is CPython-specific and stdlib-only, and it can only interrupt Python-level
  progress. A stall inside one native call would need an out-of-process optimizer, which is a new
  decision against ADR-0024.

## Decision

- **Payload-only frames.** Optimization frames are additive, optional payload fields. `TSStep`
  gains `coordinates_angstrom` (eta's own P-RFO, every step). geomeTRIC runs gain
  `OptimizationFrame`s captured at eta's own `Bridge.calc_new` hook after each evaluation, in
  success **and** failure rows (a timed-out or failed pre-relax keeps its path). Accepted steps are
  labelled only from geomeTRIC's output file (`xyzout`); otherwise the list is labelled as engine
  evaluations including trial points.
- **Keys unchanged.** Stage keys are unchanged, and frames never alter a result.
- **Forward-only stores.** A v0.6.0 reader refuses v0.7.0 rows. A v0.6.0 row read by v0.7.0 shows
  "no trajectory stored".
- **Temp cwd.** Each geomeTRIC call runs with a per-run temporary directory as cwd, restored in
  `finally` under a lock.

## Consequences

- No recomputation and no cache invalidation. The cost is store size, which is measured and
  decimated in the run-data, never in the store.
- Mixing versions in one store is loud, not silent. The v0.7.0 Phase 3 bundle gates that every
  trajectory has frames, so a reused old store cannot pass it.
- The repo and any caller's cwd stay clean of geomeTRIC files.
