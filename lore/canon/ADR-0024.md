Never call `geometric.optimize.run_optimizer`: it calls `logging.config.fileConfig` on every run, which closes every existing host logging handler (red team F2, measured), and no snapshot/restore can reopen them. `GeometricOptimizer` drives geomeTRIC's lower-level API (`OptParams`, `Molecule`, `CoordSysDict`, `Optimizer(...).optimizeGeometry()`) inside a fresh temporary directory, gives the `geometric` logger a temp-dir handler with `propagate=False` for the call and restores it after. The root logger is never touched. A three-step ladder (tric, tric_tight_trust, cartesian) is recorded in `OptimizationResult.recovery_steps`; engine errors propagate. Source: missions/release-0.3.0 R2; slice 04.
